# HTML/CSS の UI の試作(サイドバー)

UI を Slint にするか HTML/CSS にするかを決めるための試作。サイドバーの部品の決まり(`proto/slint/ui/parts.slint` と同じ中身)を JS で書き、その決まりだけを使うサイドバーを HTML/CSS で作った。偽のコアでも、本物のコアでも動く。依存は無い(Node とブラウザだけ)。

## 見る

```bash
node proto/web/build.js          # → proto/web/preview.html(1 枚で開ける。偽のコア)
```

`preview.html` は、偽の壁紙と sway で並んだ偽の窓の上にサイドバーを置いた台。右下の操作盤で、テーマ(白・黒)・透け具合・後ろのぼかし・壁紙・強調の色・窓と窓の間・画面の端との間・角丸・行の高さ・字の大きさ・窓のつなぎの段を変えられる。サイドバーは触れる(押す・右クリック・ドラッグ・細い列)。サイドバーは上から 開閉・スペース・タブ・ブックマーク の順で、今のペインの詳しい表示(分割・消音・ブックマークにするボタン)は出さない(部品 PaneBar・BookmarkButton を使わない)。

本物のコアにつなぐなら、橋を動かしてブラウザで開く:

```bash
node proto/web/bridge.js         # → http://127.0.0.1:8370/(台)・/sidebar.html(サイドバーだけ)
```

ソケットは `PRELUDE_CORE_SOCK` → `$XDG_RUNTIME_DIR/prelude/core.sock` の順。試すときはコアを別にする(`PRELUDE_CORE_SOCK=/tmp/…sock target/debug/prelude-core --state … --spaces … --no-embed`)。

## 中身

| ファイル | 役 | 本番では |
|---|---|---|
| `parts.js` | 部品の決まり(部品ごとの props と callbacks・型)と、それを守らせる仕組み | そのまま |
| `glue.js` | コアの様子 → 部品の props、部品の callback → コアの命令 | そのまま(Rust の外側から JS で呼ぶ) |
| `sidebar.js`・`sidebar.css`・`sidebar.html` | サイドバーの 1 つの作り。部品の決まりだけを使う | 使用者が差し替えられる |
| `host.js` | 画面の中のホスト。コアへの道(偽のコア・橋)を選び、サイドバーを描く | Rust の外側の窓(WebKitGTK・layer-shell)の中 |
| `fake.js` | 偽のコア(命令の名前・引数・返事は本物と同じ) | 無し |
| `bridge.js` | 本物のコアのソケット ⇔ ブラウザ(SSE と POST) | Rust の外側 |
| `stage.html`・`build.js` | 見た目を確かめる台と、1 枚の HTML にする道具 | 無し |

### 決まりを守らせる仕組み

Slint ではビルドで止まるところを、ここでは **使った瞬間** に止める(`parts.js`)。

- ホストが満たす props は、全部そろっていて型が合っていないと止まる(足りない・余計な項目も)
- サイドバーが決まりに無い部品・props を読むと止まる(`Proxy`。配列のメソッドの中でも)。props は書き換えられない
- サイドバーが決まりに無い callback を呼ぶ・引数の数や型が違うと止まる

サイドバーは頼みごとを `data-call="部品.callback"` と `data-args` で書き、描くのは HTML の文字列なので、テスト(`test/parts.test.js`。`npm test` に入る)は DOM なしでサイドバーを描き、メニューの中も含めて全部の頼みごとを実際に通して確かめる。

## 分かったこと

- **コアとのつなぎ**: 本物のコアで、タブの切り替え・ブックマークの名前の変更・フォルダから直下へのドラッグが、`.prelude` のファイルまで届いた。Slint と同じくソケットの約束だけでつながり、コアの側は何も変えていない
- **見つけた食い違い**: `bookmark.list` の `folder` はスペースの中の名前(`研究`)、部品の決まりと命令(`bookmark.move` など)はフォルダのパス。つなぎ(`glue.js`)でパスにする
- **見た目**: 色・大きさ・角丸・透け具合を `:root` の変数にし、テーマはその値を差し替えるだけ。クリア表示は、窓を透明にして半透明の色を出すだけで、後ろのぼかしは台(= コンポジタの代わり)が掛ける。窓の中のぼかし(メニューのすりガラス、`backdrop-filter`)は Slint ではできない
- **色は 3 つだけ**: 背景(`--bg`)・文字(`--fg`)・強調(`--accent`)と、透け具合(`--opacity`)。線・薄い字・面・ホバーは `color-mix()` でこの 3 つを薄めて作る(`sidebar.css` の `:root`)。赤・緑の印も使わない。台の操作盤で、白・黒・透け具合・強調の色と、アプリのアイコンを単色にするかを変えられる
- **間の決まり**: サイドバーを窓と同じ決まりで並べる(画面の端から `windows.gaps_outer`、隣の窓とは `windows.gaps_inner`。上下の端・角丸・影も窓と揃える。間が無ければ端に付ける)。台の操作盤で「窓と窓の間」「画面の端との間」「窓の角丸」を変えて確かめられる
- **このクラウドで確かめられる**: Playwright で、描画・クリック・右クリック・打つ・ドラッグを確かめ、スクリーンショットを撮れた
- まだ: WebKitGTK の窓を layer-shell で出す・日本語入力(fcitx5)・メモリと起動の速さを、画面のある PC で確かめる。ランチャー・設定の画面は作っていない
