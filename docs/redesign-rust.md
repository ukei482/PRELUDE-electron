# PRELUDE の設計(Rust 版)

PRELUDE を Electron から Rust に移すにあたっての設計。節の名前はコードのコメントから「`docs/redesign-rust.md` の「…」」の形で指されているので、変えるときはコメントも直す。決めた経緯は git の履歴にある。

## 目的

もっと使いやすく、ミニマルで、拡張しやすいものにする。

- **PRELUDE が持つのは「何をしているか」**(スペース・ブックマーク・paths・履歴)と、それを開く入口(ランチャー)だけ
- 本体は Rust。Web は Chromium そのもの、ファイラは yazi などの外のプログラムに任せる
- OS・デスクトップの役割(窓の管理・バー・通知・ロック・電源・更新)は持たない。そのかわり、どの OS・デスクトップにも載る
- 環境に合わせる部分は「つなぎ」として差し込める。つなぎが無くても使える

## 全体の形

### 3 つの層

| 層 | 中身 | 持ち主 |
|---|---|---|
| 本体 | コア `prelude-core`(状態とコマンド。画面を持たない)、`.prelude`・`space.toml`(`prelude-format`)、ソケットの約束(`prelude-proto`)、`prelude` コマンド、ランチャー `prelude-launcher` | PRELUDE。どこでも同じに動く |
| つなぎ | 環境に合わせる差し込み口: 窓(「窓のつなぎ」)、アプリのダイアログ、アプリの一覧、サイドバー | PRELUDE が既定のものを出すが、どれも無くてよい |
| 環境 | OS とパッケージの管理・更新、コンポジタ・rice、バー・通知・ロック、どこでも効くキー、ファイラ | PRELUDE ではない |

**つなぎが 1 つも無くても PRELUDE は使える**: ランチャーから、paths(作業フォルダ・最初のフォルダ)を付けてアプリ・URL・フォルダ・ブックマークを開ける。つなぎは、それをその環境でもっと便利にするだけ。

```
┌─ prelude-core(Rust・常駐。画面を持たない) ─────────────┐
│ 状態: スペース / タブ / 分割 / ペイン / .prelude / 履歴    │
│ 開く: アプリ・レシピ・Chromium(Web のペイン)            │
│ 公開: コマンドとイベント(ソケットの約束)                │
└──────▲───────────────────────────────▲──────────────────┘
       │ ソケットの約束(Unix ソケット)  │ 差し込み口
┌──────┴──────────────────────┐  ┌──────┴──────────────────┐
│ UI・コマンド                 │  │ つなぎ(環境ごと。任意)  │
│ prelude / ランチャー /       │  │ 窓(sway・KWin…)        │
│ サイドバー / 設定            │  │ ダイアログ・アプリの一覧 │
└─────────────────────────────┘  └─────────────────────────┘
```

### コアと UI の境目

| | 決めたこと | 理由 |
|---|---|---|
| プログラム | **コアと UI は別のプロセス**。間は Unix ソケット(コマンドとイベント) | UI が落ちてもタブ・開いたアプリは残り、UI だけ立ち上げ直せば戻る。`prelude` コマンドや外部のスクリプトも同じソケットを使う |
| ペインの場所 | 分割の構造(どこで左右・上下に分けたか、比率)は **コアが覚える**。実際に並べるのは **窓のつなぎ**(無ければ環境に任せる) | PRELUDE は自分の窓を持たない |
| キー | **どこでも効くキー** は環境(コンポジタ・デスクトップ)の設定から `prelude` コマンド・ランチャーを呼ぶ。PRELUDE はキーを横取りしない。**部品の中だけのキー** は部品 | どの環境でも同じ作りで動く |
| 覚えること | **残すものはコア**(スペース・タブ・分割・開いているブックマーク)。**UI は今の見た目だけ**(付け替えたら消えてよいもの) | UI が落ちても・付け替えても作業が消えない |

- **ほぼ全部の機能がコマンドで完結する。** UI(ランチャー・サイドバー)にだけ許された操作は作らない。環境のキーはあってもよいが、それが無いとできない操作も作らない

### リポジトリ
- このリポジトリに Cargo のワークスペース(`crates/`)と UI のワークスペース(`ui/`)を置く。Electron 版は Rust 版が日常の用途を満たすまでリリースとして残し、満たした時点で消す。`.prelude` の形式とテストを両方で確かめられる(`test/fixtures/format/`)

## スペースとブックマーク

### 考え方
- **保存先を決めるのは「プロセス(何をしているか)」** で、「プロセッサ(どのアプリか)」ではない
- **スペース = 1 つのプロセス** = フォルダ 1 つ。ホームからコマンドで切り替え、切り替えると今のタブは全部閉じ、切り替え先のブックマークを読み込む
- **`.prelude` = ブックマーク 1 つ**。スペースのフォルダの中にたくさん置く。ブックマークのフォルダは、スペースの中の本物のフォルダ
- **`paths` はブックマークが持つ**。スペースは、ブックマークに書いていないときの既定の `paths` を持つ

### 形

```
~/スペース/
└── 論文執筆/                 ← スペース(フォルダ) = 1 つのプロセス
    ├── space.toml            ← スペースの設定: 既定の paths
    ├── 本文.prelude           ← ブックマーク 1 つ
    ├── 文献を探す.prelude
    └── 執筆/                  ← ブックマークのフォルダ(本物のフォルダ)
        └── 図.prelude
```

```toml
# space.toml — ブックマークに書いていない項目の既定
[paths]
files    = "~/研究/論文"
terminal = "~/研究/論文"
```

```toml
# 本文.prelude — ブックマーク 1 つ
title = "本文"

[paths]                       # 項目は自由に増やせる
open     = "~/Dropbox/文献"    # アプリの「開く」ダイアログの最初のフォルダ
save     = "~/研究/論文/原稿"   # アプリの「保存」ダイアログの最初のフォルダ
terminal = "~/研究/論文/src"    # コンソール・起動するアプリの作業フォルダ
files    = "~/研究/論文"        # ファイラの最初のフォルダ

[layout]                      # タブの配置(今の .prelude の root と同じ形)
# ...
```

### どの paths を使うか
- **今開いているブックマーク**(表示しているタブが開いたブックマーク)の `paths` を使う。アプリのダイアログ・コンソール・ファイラ・ダウンロードのどれも同じ
- 項目ごとに、ブックマーク → スペース(`space.toml`)→ `files` → ホーム の順で決める
- 今のタブがブックマークから開いたものでなければ(新しいタブなど)、スペースの既定から決める
- パスは `~/…` と、ファイルがあるフォルダからの相対パスで書ける

### 決めごと
- **ファイルには使用者が決めたことだけ** を書く。前回開いていたタブ・折りたたみの開閉など PRELUDE が変えるものは `~/.local/state/prelude/` に置く
- `[paths]` の項目は自由。読む側(ダイアログ・レシピ・ダウンロード・将来のプラグイン)は知っている名前だけを使う。**知らない項目は無視して残す**(書き戻しても消さない)
- **UI ごとの区画**: UI の部品が自分だけの情報(グループの色、使用者が決めた並び順など)を残すときは、`.prelude` / `space.toml` の `[ui.<部品名>]` に書く。部品は自分の区画だけを読み書きする。見せ方は部品が自由に決める
- 人からもらった `.prelude` の起動コマンドは、今と同じく確かめてから実行する
- `.prelude` も `space.toml` も TOML。0.11 までの JSON の `.prelude` も読む。`space.toml` は隠しファイルにしない
- `tags`(フォルダをまたぐ目印)は後回し

## ペイン

ペインは窓 1 つで、中身を描くのはほかのプログラム。PRELUDE は何を開くか(と、窓のつなぎがあれば場所)を決めるだけ。

### 種類
| 種類 | 中身 |
|---|---|
| `web` | Chromium のアプリの窓(「Web のペイン」) |
| `app` | 起動コマンドを直接書くアプリ。自分で作ったブックマークは今までどおり。人からもらったものは、インストール済みのアプリと一致しないコマンドを確かめてから実行する |
| レシピの名前(`console`・`cli`・`files`・`settings` など) | 設定ファイルで決めたコマンド(下の「レシピ」) |

- **知らない種類**(この PC にレシピ・プラグインが無い)のペインは「この種類は入っていません」と表示し、**書かれていた中身はそのまま残す**

### レシピ
設定ファイルだけでペインの種類を増やす。

```toml
# ~/.config/prelude/panes/console.toml
name = "コンソール"
run  = "konsole --workdir {paths.terminal}"   # {paths.…} は今のブックマークの paths に置き換わる
class = "org.kde.konsole"                     # 省略できる。窓を見分ける名前
```

- コンソールもファイラも特別扱いせず、レシピの 1 つにする
- `.prelude` には `type = "console"` のように **種類の名前だけ** を書く。コマンドは自分の設定にしか無いので、人からもらったファイルが勝手なコマンドを実行できない
- `{path}` はペインの `path`、無ければ paths の `files`。`{pane}` はペインの id。ペインに `cwd` があれば `{paths.terminal}` の代わりにそれを使う

### ペインの `path`
- どの種類のペインでも `path`(このペインの場所)を持てる。タブ・ペインの名前は、`path` があればその最後の名前。**コアは種類を名指ししない**
- **ブックマークの `path` は「開き始める場所」**。中で移った先は `.prelude` に書かない(「ファイルには使用者が決めたことだけ」。コアは `.prelude` を書き戻さない)。アプリのペインで、Kate が開いているファイルを追いかけないのと同じ
- 移った先は、タブの保存(`~/.local/state/prelude/`)にだけ残る。残すかどうかはファイラ次第で、`prelude pane path [--pane <id>] <フォルダ>` を呼べば残る(yazi はフォルダを移ったときのフックで呼べる)
- `type = "field"` は `files` の別名として読む(フィールド表示はやめた)。ファイラの中の状態(並べ替えの `sort`、`[ui.field]`)は形式から外す。今あるファイルは「知らない項目は無視して残す」でそのまま読める

### ファイラ: 外のプログラム、既定は yazi
- ファイルの一覧と操作は PRELUDE の外にある。自作のファイラは持たない(ミニマル。PRELUDE が持つのは paths の考え方とファイラとの約束だけ)
- 既定の `files` のレシピは `konsole --workdir {path} -e yazi {path}`。yazi は端末の中で動き、プレビューとプラグイン(Lua)を持ち、`--chooser-file` でダイアログの選ぶ画面にもなる
- Dolphin などに替えるのは `~/.config/prelude/panes/files.toml`

### プラグイン(これから)
- コアが持っていないデータ(カレンダー・タスクなど)を持ち込むときは、**別のプログラム** として作り、コアと同じソケットでつなぐ。言語は自由。プラグインが落ちても PRELUDE は落ちない
- PRELUDE の中に組み込む方法(WASM・共有ライブラリ)は、複雑さと巻き込まれて落ちる危険から採らない
- ソケットの約束が固まってから作る

## Web のペイン

Web は全部 Chromium で、PRELUDE は Web エンジンを持たない(Electron 版は WebContentsView で自前で描き、合わないサイトだけ Chromium へ逃がしていた)。

### 形
- **Chromium は PRELUDE 専用のプロファイルで 1 つだけ** 起動する。`PATH` から探し(`xdg.rs`)、snap 版ならプロファイルと印のページを `~/snap/chromium/common` に置く。無いときの扱いは作らない(パッケージが入れる)
- **Web のペイン 1 つ = Chromium のアプリの窓 1 つ**(`--app`。アドレスバーもタブも無い)。PRELUDE のタブと Chromium のタブが二重にならず、「1 ブックマーク = 最大 1 タブ」が保てる
  - `--app=` は `data:` や `about:blank` では窓にならないので、題名に印を出すだけのページ(`prelude-pane.html#<コアの印>:<ペイン>`)で開き、窓を見分けてから本当の URL へ移す
- **つなぐのは小さな拡張機能**(`crates/prelude-core/extension/`)。CDP は使わない: `--remote-debugging-pipe` で起動すると `navigator.webdriver` が `true` になり、Google のログインが「安全でないブラウザ」として拒まれる
  - 拡張機能はコアに埋め込み、起動のときに書き出して `--load-extension` で読む(Google 版の Chrome では外された引数なので Chromium を使う)。事実を知らせて頼まれたことをするだけで、判定は `web.rs` の `decide` がする
  - native messaging でつなぐ。Chromium が `prelude-core --web-host` を起動し、これがコアの Unix ソケット(`core.web`)へつなぐ。宣言は `<プロファイル>/NativeMessagingHosts/`、id は `manifest.json` の `key` で固定する
- URL・タイトルはサイドバーに出す。URL を書き換えるときは、キー 1 つで **今の URL が入った状態のランチャー** を開き、Enter で同じペインに開く。戻る・進むは Chromium のキー(Alt+←/→)。`web.go` は同じことをコマンドからするためのもの
- 権限の確認・拡張機能・パスワード・ログインは **Chromium に任せる**

### Chromium との分担

| | 決めたこと |
|---|---|
| 立ち上げ直し | **PRELUDE(コア)が戻す**。コアがペインの URL を覚えていて、開き直させる。Chromium 自身の「前回のページを開く」は切る。ページ内の戻る履歴・スクロール位置・入力途中のフォームは戻らない |
| 新しい窓 | タブ付きの窓(`normal`)に出た http(s) のページは閉じて **PRELUDE の新しいタブ** にする。ログインなどの小さな窓(`popup`)は取り込まず、浮かせたまま前に出す |
| ダウンロード | 保存先は **ダウンロードを始めたタブのブックマークの `paths`**(`download` → `save` → スペースの既定…)。拡張機能からは絶対パスで頼めないので、終わってからコアが移す |
| プロファイル | **1 つだけ**。どのスペースでも同じログイン状態。スペースごとに分ける(`space.toml` の `profile`)は、要るようになったら足す |
| 終わり | Chromium は窓が無くなると終わる。次の Web のペインで起動し直す |

## 窓のつなぎ

コアは窓を持たない。窓はつなぎ(`compositor.rs` の `Compositor` のトレイト)に任せ、rice(sway など)・KDE など、それぞれの決まりに合わせる余地を残す。

### 段
つなぎは、できることを段で名乗る。コアは段 0 だけで成り立つように作り、上の段はつなぎがあるときだけ使う。

| 段 | できること |
|---|---|
| 0. 無し | アプリを起動するだけ。置き場所は環境に任せる(`plain.rs`) |
| 1. 並べる | ブックマークを開くときに `[layout]` のとおりに並べる |
| 2. 読む | 今の並びを読む(タブの保存・ブックマークの配置を書くとき) |
| 3. 追う | 窓の動き・PRELUDE を通さずに開いた窓を追いかけて、コアの状態に合わせる |

- `[layout]` は分割の木と比率。つなぎが無ければ「開くものの一覧」として読む
- 対応するコンポジタが無ければ、つなぎ無し(`plain.rs`。段 0)で動く。アプリはペインごとに 1 回だけ起動し、Web のペインの Chromium の窓も環境が置く。`--no-embed` はアプリも起動しない(状態だけを試す)
- 今のつなぎの名前と段は、状態の `windows`(`backend`・`level`)に出す
- 分割で開く(ランチャーの Ctrl+→ など)は、つなぎが並べられるときだけ出す
- 窓の持ち主を見分ける `/proc`(`procs.rs`)や窓の印は、つなぎの中の事情として扱う

### 取り合わない決まり
窓の配置の本当の持ち主はコンポジタ(と、それを操作する使用者)。PRELUDE は頼まれたときに並べ、あとは記録するだけにする。2 つのプログラムがそれぞれ「正しい配置」を持って押し付け合うと取り合いになるので、**どのつなぎも、どの段でも次を守る**。
1. **並べるのは頼まれたときだけ**(ブックマークを開いた・PRELUDE の命令で分割した)。覚えている配置と違っても、戻さない
2. **使用者・環境が動かしたら、それに合わせる**(読み戻してコアの状態を直す)
3. **浮いた窓は触らない**(取り込まない・タイルに戻さない)
4. **環境の窓の決まり(window rules など)を上書きしない**
5. **フォーカスを奪わない**(使用者が選んだものと取り合わない)

- 並べ方に木の無いコンポジタ(Hyprland の dwindle など)では、比率を押し付けると並べ方と押し合いになる。開くときに大まかに並べるまでにする
- 使用者が「どこまで任せるか」を選べるようにする(設定の「任せる段の上限」。段 0 にすれば起動だけ)

### 段 0 でできること・できないこと
段 0 でも、PRELUDE の一番の価値(スペース・ブックマーク・paths の効き目: 作業フォルダ・ダイアログ・ダウンロード)は残る。効かなくなるのは窓に関わるもの: ブックマークの配置(全部を起動するだけ)、タブ = 作業領域(見ている作業領域に開く)、窓が閉じたことを知る、今のペイン、分割で開く。
- 小さく直せるもの: **PRELUDE でペインを閉じたら、起動したプロセスを終わらせる**(頼まれたときだけなので取り合わない)。**起動したプロセスが終わったら、ペインを止まったことにする**(すぐ本体に頼んで終わるアプリもあるので、完全ではない)

### 作業領域だけ指定する形(案)
段 0 と段 1 の間に、配置を環境に任せきったまま、タブの意味を保つ形がある。
- ブックマークを開くとき、コンポジタに「このアプリをタブの作業領域に開いて」とだけ頼む(Hyprland なら `exec` に作業領域を付ける)。並べ方・大きさ・浮かせるかは、すべて環境に任せ、開いた後は何もしない
- 作業領域が切り替わったことは、コンポジタのイベントを **読むだけ** で知る(タブの切り替えになる)
- 「タブ = 作業領域」と「開くと作業領域にアプリがそろう」は保ち、取り合いは起きない。Omarchy のように、作業領域の移り方(`Super + 数字`)が環境で決まっているところに合う

### タブ
- **タブは「開いている作業」**(どのブックマークを開いたか・何を開いたか)という論理の単位。作業領域・仮想デスクトップ・タブのどれに当てるかはつなぎが決める
- sway では **スペース = 作業領域の組、タブ = 作業領域 1 つ(名前はタブの番号)、ペイン = 窓 1 つ**。窓と作業領域があるかどうかは sway が持ち、それが何か(どのタブ・ブックマーク・スペースか)はコアが持つ。コアは IPC のイベントで対応表を合わせる。コンポジタ自身のタブの見た目(Hyprland のグループのバーなど)は隠す

### PRELUDE を通さずに開いた窓
段 3 のつなぎだけが引き取る。

| 窓 | 扱い |
|---|---|
| 普通の窓(Dolphin から開いた Okular など) | **今のタブのペインに入れる** |
| 親のある窓(ダイアログ・ログインのポップアップ・確認の窓) | **浮かせる**。タブのペインにはしない |

- `[layout]` に残すのは **開き直せる窓だけ**(インストール済みのアプリ = `.desktop` と一致するもの)。開き直せない窓はタブにはいても書かない
- 窓ごとの例外(このクラスはいつも浮かせる、など)は設定で足せる

### 既定のつなぎ
| つなぎ | 段 | 中身 |
|---|---|---|
| sway・SwayFX | 3 | `sway.rs`(i3 の IPC)。配置の木を sway の分割として組み、sway の木を読み戻してコアの木に合わせる |
| KWin | 1 | `embed.rs`・`embed.js`。KWin には木構造の並べ方が無いので、配置の木から場所を出して窓を重ねる。KDE で使う人のために残す(保守が重くなったら段を下げる) |

- Hyprland・GNOME などは、要る人がつなぎを足せる。Hyprland なら hy3(i3 風の木構造のプラグイン)が `[layout]` に合う。素の Hyprland は比率を戻しにくく、niri はスクロール型で形が合わない
- つなぎのトレイトには版を付けない(下の「UI」の「トレイトの版」)

## アプリのダイアログ

アプリの「開く」「保存」のダイアログの最初のフォルダを、今のブックマークの paths にする。xdg-desktop-portal のある環境だけのつなぎ。

- xdg-desktop-portal の FileChooser のバックエンド(`portal.rs`)は、コアとは別のプロセス(`prelude-core --portal`。コアが起動のときに子として起動し、終わるときに止める)。最初のフォルダはコアのソケットの `dialog.folder` で聞くだけで、コアが動いていなければアプリが頼んだフォルダを使う。選ぶ画面は `~/.config/prelude/chooser.toml` のプログラム
- 最初のフォルダは「保存し直すファイル(`current_file`)のフォルダ → 今のブックマークの `paths.save` / `paths.open` → アプリが渡した `current_folder` → ホーム」の順(アプリが前回のフォルダを渡しても、ブックマークの保存先が効くように)
- **選ぶ画面の既定は yazi**(スクリプト `prelude-choose`)。`{mode}`・`{path}`・`{name}`・`{output}` を受け、`konsole -e yazi --chooser-file {output} {path}` を起動する。選ぶ画面の窓は `PRELUDE_DIALOG=1` で見分けて浮かせる
  - 保存: yazi には新しい名前を打つ画面が無いので、xdg-desktop-portal-termfilechooser と同じく、最初のフォルダに保存する名前の仮のファイルを置いて yazi で選んでもらう(名前を変えても、別のフォルダへ移ってもよい)。終わったら・取り消したら仮のファイルを消す
  - フォルダを選ぶときの操作は実装で確かめる
- `portals.conf` で環境のものと置き換え、外せば環境のダイアログに戻る(`scripts/portal.sh`)。ポータルを使わないアプリ(自前のダイアログを出すもの)には効かない

## UI

PRELUDE の UI はランチャー・サイドバー・設定だけ。PRELUDE の窓の中にペインを並べる形はやめた(窓を並べるのは環境)。バー・通知・OSD・クイック設定は作らず、表示用の出口(`prelude watch` の JSON)だけを出す。

### Slint
- UI はすべて Slint で作る。見た目は `.slint` に書き、ビルドのときに Rust のコードにする(`slint-build`)。コアとのやり取りは Rust(`prelude-proto`)
- 理由:
  - 軽い。試作では初回のビルドが 5 分ほど、release の実行ファイルが 29MB(GPUI は 30 分ほど・1 つ 38MB で、Zed のコミットと Rust の版に縛られていた)
  - 1.x で安定していて、資料が多い。Linux・macOS・Windows で動き、ほかの OS への道もふさがない
  - 入力欄(日本語入力)・一覧・ボタンなどの部品が最初からある
  - **決まりを書ける**: 部品の決まりは `.slint` の `global`(表示するもの = `in property`、頼むこと = `callback`)に書く。名前や型の合わない `.slint` はビルドで止まり、使用者が置いた `.slint` を実行時に読むときは、読む前に確かめて断れる(下の「付け替え」)
- 引き受ける弱み: 見た目を Rust ではなく `.slint` という別の言語で書く
- GPUI(Zed の UI)でも作ったが、ビルドの重さと Zed への依存から Slint に替えた

### 部品の約束
部品は「**何を表示し、何を送るか**」だけを約束として決め、見た目と並べ方は決めない。

| 部品 | 受け取る状態 | 送るコマンド |
|---|---|---|
| サイドバー | 部品の組み合わせ(下の「サイドバー」の「部品」) | 同じ |
| ランチャー | 候補と点数(`item.list`) | 開く・分割で開く(`item.open`) |
| 設定 | 設定の項目 | 設定を変える |

### 付け替え
| 段 | 付け替えるもの | どうやって |
|---|---|---|
| テーマ | 色・字・余白 | `theme.toml`。全部の UI が同じ値を使う |
| 見た目 | サイドバーなどの見た目と並べ方 | `.slint` を置き換える。決まり(`global`)を満たすかを、組み込むならビルドのとき、使用者が置くなら読み込むときに確かめる |
| プログラム | ランチャー・サイドバーを丸ごと | ソケットの約束だけでつながるので、別のプログラムに替えられる(fuzzel など) |

- 決まりは部品ごとの `global`(サイドバーなら `SidebarFrame`・`Spaces`・`Bookmarks`・`Tabs`・`NewTab`・`PaneBar`・`BookmarkButton`)。中身を付けるのは PRELUDE の Rust の側で、`.slint` はこれ以外の方法でコアとやり取りしない。試作(`proto/slint/ui/prelude.slint`)は 1 つの `global Prelude` で確かめた

### 決まりの版
- 窓のつなぎのトレイトと、組み込む `.slint` の決まりには版を付けない。一緒にビルドするので、合わないところはビルドの時点でエラーになる
- 版の決まりが要るのは、別のプログラム同士が話すソケットの約束(`prelude-proto`)と、使用者が置く `.slint` の決まり(`global`)。`global` は項目を足すだけなら版を上げない(使わない項目があってもよい)

### ランチャー
- 本体の一部で、PRELUDE の入口。つなぎが無い環境でもこれだけで使える
- コアが候補と点数(`item.list`。タブが先、ブックマーク・アプリ・ほかのスペースは履歴の点数の順)を出し、選んだものをコアが開く(`item.open`)。設定・PRELUDE CLI・サイドバーの開閉・分割・閉じるも、ランチャーの COMMANDS から行う
- 既定は Slint の `prelude-launcher`。fuzzel などにも替えられる(`prelude items | fuzzel --dmenu | prelude open`)
- 窓の出し方は環境に合わせる(layer-shell があればそれ、無ければ浮いた普通の窓)

### サイドバー
**サイドバーは画面の左端に layer-shell で貼り付き、場所を予約する**(ほかの窓はその右に並ぶ)。layer-shell の無い環境(GNOME・ほかの OS)では普通のウィンドウで出す。サイドバーはつなぎの 1 つで、無くても PRELUDE は使える。

- Wayland の app_id・X11 のクラス・layer-shell の名前空間は `prelude-sidebar`。**ペインではない**: `[layout]` に書かず、タブにも入らない。窓のつなぎは、普通のウィンドウで出たときも引き取らない
- 1 つだけ動く。`prelude sidebar show` は、動いていなければ起動し、動いていれば出す。`prelude sidebar hide` は止める
- サイドバーも同じソケットの約束を使い、サイドバーにだけ許された操作は作らない。ほかの人が別のサイドバーを作ることもできる
- Slint で作る。Slint の標準の窓(winit)は layer-shell を持たないので、layer-shell の面は Slint の「自前のプラットフォーム」で作る(Wayland のつなぎに smithay-client-toolkit を使う見込み)。日本語入力を含めて、試作で確かめてから作る

#### 部品
サイドバーは次の部品の組み合わせ。**部品ごとに決まり(Slint の `global`)を 1 つ持ち**、表示するもの(`in property`)と頼むこと(`callback`)だけを決める。見た目と並べ方は決めない。部品を差し替える・並べ替える・使わないのは自由で、使う部品の決まりだけを満たせばよい。

| 部品(決まり) | 表示するもの | 頼むこと | コアの命令(※ は足すもの) |
|---|---|---|---|
| 枠(`SidebarFrame`) | つながっているか・理由、細い列か、窓のつなぎの段(`windows.level`) | 幅の切り替え(つまみ)、隠す | 無し(幅はサイドバーが覚える) |
| スペース(`Spaces`) | 今のスペース、スペースの一覧 | 切り替える、作る | `space.switch`・`space.create` |
| ブックマーク(`Bookmarks`) | ブックマーク(題名・番号 b1…・種類・アイコン・開いているか)、フォルダ(題名・開閉・中に開いているものがあるか) | 開く、フォルダの中を全部開く、名前を変える、フォルダへ移す・フォルダから出す、並べ替える、フォルダで見る、ゴミ箱へ、フォルダを作る・名前を変える・中身を残して消す、フォルダを開閉する | `bookmark.open`、※ `bookmark.rename`・`bookmark.move`・`bookmark.reorder`・`bookmark.trash`・`folder.create`・`folder.rename`・`folder.remove`。開いているかはタブの `bookmark` から、開閉はサイドバーが覚える |
| タブ(`Tabs`) | タブ(番号・題名・種類・アイコン・今のタブか・開いたブックマーク)、分割したタブのペイン(種類・題名・アイコン・今のペインか)、閉じたタブがあるか | 切り替える、閉じる、ペインへ移る、並べ替える、複製する、番号を変える、下のタブを閉じる、閉じたタブを開き直す | `tab.activate`・`tab.close`・`pane.focus`・`tab.move`、※ `tab.duplicate`・`tab.renumber`・`tab.reopen` |
| 新しいタブ(`NewTab`) | 開ける種類(Web・レシピの一覧) | 種類を選んで開く(Web はランチャーを出す) | `tab.open`・`recipe.list` |
| 分割ボタン(`PaneBar`) | 今のペイン(種類・題名・URL)、分割できるか(段が 1 以上)、消音できるか・消音中か(Web) | 右・下に分割する(ランチャーを分割の向きで開き、出すものを選ぶ)、今のペインを閉じる、URL を変える(今の URL が入ったランチャー)、消音 | `pane.close`、※ `web.mute`。分割は `prelude-launcher --split row\|col`、URL は `--pane <id> --url <URL>` |
| ブックマークボタン(`BookmarkButton`) | 今のタブがブックマークから開いたものか(その題名)、ペインがいくつか | ブックマークにする(1 つのペインならそのペイン、分割していれば配置ごと)、今の配置で上書きする | ※ `bookmark.save`・`bookmark.overwrite` |

決まりは `proto/slint/ui/parts.slint`(全部を使う見本は `parts-check.slint`。コンパイルが通ることを `proto/slint` のテストで確かめる)。UI を作るときに本番の場所へ移す。

共通の見た目の部品(行・アイコン・右クリックのメニュー・名前や番号を打つ入力欄・ドラッグの印)は決まりを持たず、どの部品からも使う。右クリックのメニューに出す項目は、それぞれの部品の「頼むこと」。

#### サイドバーだけが覚えること
見た目だけの状態は、コアに持たせずサイドバーが `$XDG_STATE_HOME/prelude/sidebar` に覚える(`prelude_proto::sidebar`)。
- 幅(広い ⇄ 細い列)。`prelude sidebar toggle`・`wide`・`compact` はこのファイルを書き換え、サイドバーはそれを見て幅と予約する場所を変える
- ブックマークのフォルダの開閉

#### コアに足すもの
済(2026-11-11)。ブックマークを書く処理は `bmwrite.rs`、ゴミ箱は `trash.rs`、アプリのアイコンは `icons.rs`。どの命令も `prelude` コマンドからも使える。
- 命令(上の表の ※): ブックマークを書く(`bookmark.save`・`bookmark.overwrite`・`bookmark.rename`・`bookmark.move`・`bookmark.reorder`・`bookmark.trash`)、ブックマークのフォルダ(`folder.create`・`folder.rename`・`folder.remove`)、タブ(`tab.duplicate`・`tab.renumber`・`tab.reopen`。閉じたタブはコアが覚える)、`web.mute`
- 状態に足す項目: ブックマークの番号(並び順はコアが持ち、ランチャーの `b3` と同じ番号にする。順は `space.toml` に書く)と種類、ペインのアイコン(アプリは `.desktop` のアイコンのファイル、Web はファビコンをコアが保存したファイル)、閉じたタブがあるか、Web のペインの消音
- ブックマークを書く命令は、「ファイルには使用者が決めたことだけ」の例外ではない。使用者がサイドバーで頼んだことを、コアが代わりに書く

### Slint の試作で分かったこと
`proto/slint`(サイドバーの形の試作。手順と細かい結果は `proto/slint/README.md`)。

- **決まり**: `global Prelude` の名前を間違える・型を間違える・決まりに無い頼みごとを書くと、ビルドで止まる。実行時に読む `.slint` は、似せた `global` を自分で作ったものも含めて、読み込む前に断れる(`slint-interpreter`)
- **ビルド**: Slint 1.18.1、Rust 1.92 から。初回の debug が 5 分、release が 4 分 19 秒(4 コア)。release の実行ファイルは 28.8MB(strip で 21.6MB)
- **字**: ソフトウェア描画でも、漢字・かな・半角カナ・丸数字・絵文字が出る(システムのフォントから探す)
- **描き方**: OpenGL(femtovg)と CPU(software)を `SLINT_BACKEND` で選べる
- まだ: 日本語入力(fcitx5)・普通のウィンドウとしての振る舞い・一覧のスクロールを、画面のある PC で確かめる

## ソケットの約束

型は `crates/prelude-proto` が正。ここは見取り図。

- 場所: `$PRELUDE_CORE_SOCK` → `$XDG_RUNTIME_DIR/prelude/core.sock`。フォルダは 0700、ソケットは 0600
- 1 行 1 つの JSON(1 行は 1MB まで)。送る: `{"id": 1, "cmd": "tab.open", "args": {...}}`(`args` は省ける)。返る: `{"id": 1, "result": …}` か `{"id": 1, "error": {"code", "message"}}`
- 最初に `hello {protocol, name, subscribe}`。版が合わなければ `protocol` のエラー。`subscribe` すると、すぐに今の状態、その後は変わるたびに `{"event": "state", "data": State}`
- コマンド: `state.get`、`space.list / switch / create`、`bookmark.list / open`、`tab.open / close / activate / move`、`pane.split / close / update / focus / place`、`split.ratio`、`paths.get`
- 配置は `.prelude` の `[layout]` と同じ形で、ペインに `id` が付く。タブは `{"id"}` か画面の番号 `{"num"}` で指し、省くと今のタブ
- エラーの種類: `bad_request`・`unknown_command`・`protocol`・`not_found`・`conflict`・`io`
- 版の決まり: コマンド・項目・イベントを **足すだけなら版は上げない**(受け取る側は知らないものを無視する)。意味を変える・消すときは版を上げ、コアは古い版も話し続ける(`SUPPORTED`)

ランチャーの候補で足したもの: `item.list`(→ `Item { key, kind, label, detail, score }`)、`item.open { key, allow }`。key は `tab:<id>`・`bookmark:<パス>`・`app:<.desktop の id>`・`space:<名前>`。開いたもの(`bookmark.open`・`space.switch` も)は点数に足す

段階 3-a で足したもの: `recipe.list`、`bookmark.open` の `allow` と返事の `held`(外した起動コマンド)、ペインの `window_title`・`stopped`。取り込みの D-Bus は `org.prelude.Core`(`/org/prelude/Core` の `Report`。KWin スクリプトが呼ぶ)

段階 3-b で足したもの: `web.go`、`download` のイベント

サイドバーの部品のために足したもの(2026-11-11): `tab.duplicate`・`tab.renumber`・`tab.reopen`、`bookmark.save`・`bookmark.overwrite`・`bookmark.rename`・`bookmark.move`・`bookmark.reorder`・`bookmark.trash`、`folder.list`・`folder.create`・`folder.rename`・`folder.remove`、`web.mute`。状態に `windows`・`closed`・`bookmarks_rev`、`bookmark.list` に `num`・`kind`、配置のペインに `icon`(ファイルのパス)・`muted`。どれも足しただけなので、版は 1 のまま

ブックマークのフォルダの監視: コアが 2 秒ごとにスペースのフォルダ(直下と 1 段下)の中身の印を比べ、外から変わったら `bookmarks_rev` を上げて知らせる。OS の監視の仕組み(inotify など)には頼らない(ほかの OS にも載るように)

まだしていないこと: ショートカット、`prelude-core` を systemd で常駐させること、UI の窓より上に取り込んだ窓を出し直すこと(UI ができてから。今は最前面に置くだけ)

## 環境に任せるもの

| 役割 | 扱い |
|---|---|
| デスクトップの外回り(バー・通知・トレイ・OSD・音量・ロック画面・ログイン画面) | 作らない。Electron 版の `sys/`・`theme/`・`scripts/shell-mode.sh` などは Rust 版へ移さず、Electron 版と一緒に消す |

作者の PC は NixOS + SwayFX + 自分の rice。PRELUDE の前提ではない。中身と NixOS に移った記録は [rice.md](rice.md)。

## AI 連携

PRELUDE の「何をしているか」(スペース・ブックマーク・paths)を AI に渡せるようにする。Omarchy から学んだとおり、「テキストの設定 + 揃ったコマンド」で AI が操作できる土台を作り、「スキル」で操作のしかたを教える。

### スキル
- `skills/prelude/`(`SKILL.md`・`format.md`)。考え方・守る決まり(操作はコマンドで、ブックマークを動かすのは `prelude bookmark …`、消すときはゴミ箱、スペースの外を書かない、人からもらった起動コマンドは確かめる、窓を押し付けない)・よくある頼みごと・ファイルの形
- `prelude` コマンドに埋め込み(入っている版と中身が必ず合う)、`prelude skill install` で `~/.agents/skills`(Omarchy・Codex なども使う)と `~/.claude/skills` に書き出す。ほかのスキルは上書きしない。NixOS のモジュールはログインのたびに書き出す

### MCP
- `prelude mcp`: 標準入出力の MCP のサーバー。コアの命令をツールにする(状態・一覧を読む、開く、タブ・ペイン・Web・スペース・ブックマーク・フォルダの操作)。対象の指し方は `prelude` のコマンドと同じ(名前・フォルダ/名前・b3・パス)
- 読むだけのツールに `readOnlyHint`、消す・閉じるツールに `destructiveHint`
- **人からもらったブックマークの起動コマンドは、AI からは実行させない**。`--run`(`allow`)にあたるものは出さず、外したコマンドは返事で知らせて、使用者に任せる
- コアには命令ごとにつなぐ(コアが起動し直しても続けられる)

### AI のペイン
- 既定のレシピ `agent`(名前は「AI」): 端末を今のブックマークの作業フォルダ(`{paths.terminal}`)で開き、`prelude agent` を動かす。ブックマークごとに、その作業のフォルダで AI が始まる(PRELUDE の paths が活きるところ)
- `prelude agent [頼みごと]`: 既定の AI を今のフォルダで起動する(プロセスを置き換える)。AI は環境変数 `PRELUDE_AGENT`(シェルのコマンドとして読む)、無ければ PATH から claude・codex・gemini・opencode の順。最初の頼みごとは、渡し方が分かる AI(claude・codex・gemini)にだけ渡す
- 既定の AI を設定ファイルで選べるようにするのは、「設定」で決める

## Omarchy から学んだこと

Omarchy(Arch + Hyprland + Quickshell の自前のシェルを、作者の好みで丸ごと配るもの。2026 年 8 月の 4.0)を読み、PRELUDE と比べた(2026-11-11)。`.prelude` のような「何をしているか」の形は無いが、理想に近いところが多い。**乗る先は Nix のままにする**(移行の手間と、Omarchy に全部を任せると広く使えなくなるため)。Omarchy は、PRELUDE が載る環境の 1 つとして扱う。

### PRELUDE に足りないもの
PRELUDE は「何をしているか」のデータの形(スペース・`.prelude`・paths)が強い。足りないのは **使う人が触れる面(体験の層)**。

| Omarchy の柱 | Omarchy では | PRELUDE に足りないもの |
|---|---|---|
| おまかせの完成形 | 入れた瞬間から全部そろって動く | 環境ごとの **おすすめの組み合わせ**(下) |
| 1 つのメニューから全部 | メニューから何でもでき、ランチャーも統合。項目は JSONC で足せる | PRELUDE の命令を全部並べる、広げられるメニュー |
| キーの決まり | 修飾キーごとに役割を分ける(`Super` = システム、`Super + Shift` = アプリ…)。キーの一覧を出せる | おすすめのキーの割り当て(環境に足す断片)と一覧。PRELUDE はキーを横取りしない |
| コマンドの台帳 | `omarchy <分類> <命令>` に揃い、スクリプトの頭のメタデータから、ヘルプ・一覧・JSON・テストを作る | **命令の台帳を 1 か所に**。ヘルプ・JSON・ランチャー・MCP・スキルをそこから作る |
| 設定の層 | 既定は触らない場所、自分の変更は `~/.config`。既定に戻すコマンド、編集すると自動で反映 | 既定のファイル + 使用者の上書き、`prelude config`、変更の反映(今は既定がコードに決め打ち) |
| テーマの統一 | 1 回の切り替えで、端末・エディタ・ブラウザ・シェル・ロック画面まで変わる | 環境のテーマに **ついていく** 仕組み |
| 窓の決まり | dwindle が既定、作業領域ごとに並べ方を変えられる、画面ごとに作業領域 1〜10、画面を抜いたときの扱い | **複数の画面**、タブごとの並べ方、取り合わない決まり(上の「窓のつなぎ」) |
| 更新と移し替え | 更新のたびに移し替えのスクリプトを流し、使用者の設定を新しい版に合わせる | 設定・形式が変わったときの移し替え |
| フックとプラグイン | 出来事の後にスクリプトが動く。プラグインは git から入れる | 出来事のフック(スペースを替えた・ブックマークを開いた…) |
| 使う人への説明書 | 40 章以上の manual | **使う人向けの説明書**(今は開発者向けの設計書だけ) |
| AI | スキル・共通の指示ファイル・既定の AI・落ちたときの診断 | スキル・MCP・AI のペイン(「これから」) |
| 作る側の仕組み | AGENTS.md に作業ごとの手引き、文書を読む人ごとに分ける、画面のテスト・仮想マシンでのテスト | 文書の分け方、画面のテスト |

### OS の役割を持たない、との両立
Omarchy は OS ごと持つことで完成形を作っている。PRELUDE は同じやり方をしない代わりに:
- **PRELUDE 自身の面を磨く**: 命令の台帳・メニュー・設定の層・フック・説明書は、PRELUDE の中だけで作れる
- **環境ごとの「おすすめの組み合わせ」を配る**: 環境の上に載せる設定の束。例えば Omarchy 向けなら、任せる段は「作業領域だけ指定」、端末は foot、AI は Omarchy の既定、テーマは Omarchy についていく(フック)、メニューの項目(`omarchy-menu.jsonc`)とキーの断片を足す。OS にはならずに、入れた瞬間から気持ちよく動く状態に近づける

### Omarchy の上で PRELUDE が使うところ
- 窓: Hyprland。今はつなぎが無いので段 0 で動く。つなぎは「作業領域だけ指定」から作る
- サイドバー: Hyprland は layer-shell に対応。Omarchy のバーのプラグインとして PRELUDE の部品を作る道もある
- ランチャー・バー: メニューの JSONC に PRELUDE の項目、バーのプラグインで `prelude watch --bar`
- AI: Omarchy は `~/.agents/skills` を各 AI にリンクするので、PRELUDE のスキルをそこに置けば Omarchy の AI 全部が使える
- 配布: Arch 用の PKGBUILD が要る

### 引き継ぎ
- 試している間、**Electron 版と Rust 版は同じデータを使う**(同じ `~/スペース` の TOML の `.prelude`・`space.toml`)。Rust 版で足したブックマークは Electron 版にも出る
- 初めて Rust 版を起動したとき 1 回だけ、次を引き継ぐ(`migrate.rs`):

| もの | 引き継ぎ方 |
|---|---|
| ブックマーク(`config.json` の `bookmarks`、`~/ブックマーク/*.prelude`) | `~/スペース/Main/` に 1 つずつ `.prelude` として書き出す(PR #66 と同じ)。サイドバーのフォルダは本物のフォルダにする |
| 色・フォント(`appearance`) | `theme.toml`(壁紙は rice に任せるので引き継がない) |
| 動き(`behavior`) | `settings.toml`。Rust 版で無くなる設定(`chromiumSites` など)は `migrated.txt` に一覧にして知らせる |
| ショートカット(`shortcuts`)・タブの開き方(`tabs`) | 引き継がない。キーは環境が受ける |
| 前回のタブ(`workspace*.json`) | 引き継がない(スペースのブックマークから開き直せる) |
| Web のログイン | 引き継がない。NixOS の Chromium は `~/.config/PRELUDE-electron/browser-profile` を使い、Kubuntu の snap 版の `prelude-profile` は移さない(Cookie は鍵で暗号化されていて、移しても残るとは限らない)。**足りないサイトは一度ログインし直す**(2026-11-05 決定) |
| 元のファイル | 消さない。いつでも Electron 版に戻れる |
